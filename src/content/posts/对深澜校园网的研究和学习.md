# 正文  

## 信息收集
我开始在军训和学前教育的空隙时间，观察校园网络设备的分布，学校的机房服务器部署服务器集群与宽带出口链路（就是把内外网隔开），布线系统搭建分层式校园计算机网络，采用星型拓扑架构实现网络信号的全域覆盖，将网络分发至教学楼、实验室、操场和寝室。
|编号|层级|设备|作用|
|---|---|---|---|
|1. |**核心层**|机房核心交换机、出口路由器、服务器集群、|作为整个校园网的枢纽，负责数据转发、出口路由、网络管控
|2.| **汇聚层**|楼宇汇聚交换机|负责各楼栋区域的流量汇聚，承接核心层信号，向下分发至接入层
|3.| **接入层**|教学楼、实验室、操场、宿舍楼的接入交换机、无线 AP、有线信息面板|实现终端设备的网络接入
|4. |**园区综合布线系统**|光纤主干链路、双绞线水平布线|实现机房到各建筑、区域的物理信号传输
|5.| **全域网络覆盖**|有线局域网 + 无线 WLAN 覆盖教学区、实验区、公共活动区、宿舍生活区
|6.| **出口宽带链路**|校园网上联运营商公网宽带|实现内网与互联网互通
## 开始思考
绕开校园网的认证，在我的理解中就是学校局域网内有扇大门堵住了，我们通过这条网络链接到外网。现在常见的技术有以下几种
|编号|名称|原理|使用情况|
|---|---|---|---|
|1. |隧道转发|**校园内网里，有另一台已经登录认证的主机，作为你的隧道中转服务器**|实验室免认证的电脑|
|2.|MAC 地址克隆|修改自己网卡 MAC，复制另一台**已经认证上线设备**的 MAC 地址，冒充它上网|寝室哥们买了校园网卡愿意把他的mac地址分享给你|
|3.|流量伪装|规避校内之后的网页内容限流、防火墙过滤，就是用校内账号通过验证，流量通过服务器端口转发而非校园网端口|原始没有购买校园网账号，通过购买服务器将流量转发，需要学校内有漏洞端口可以走|
|4.|网络共享 / 热点中继|一台电脑 / 手机登录校园网认证，开启热点、网卡共享，其他设备连接它上网|寝室一个人买校园网，开热点给其他人用|
|5.|免认证漏洞端口 / 放行地址|极少数情况下校园网关配置存在疏漏，会放行少量外网地址，不需要认证即可访问|学校管理员有次就让我用上了，当时还没发觉，简单理解就是没有购买校园网，但可以通过校园网访问外网了|
|6.|二层旁路、VLAN 切换|这个简单说就是把自己的账号设置成白名单免认证|基本很难实现，需要攻破很多东西，且非常可刑|

最后我选择了方案五执行，方案一因为我太菜了进不去实验室，方案二三四，需要花钱且被大家知道，不安全，我当时的思路就下面几个  
1. 通过已购买校园的账号，接入寝室ap面板，拿到管理账号，把我的设备设置成白名单  （这是一个很严重的认知错误，因为这是两套账号密码）
2. 通过抓包抓取返回认证的post包，通过解码还原密码（这是当时的想法，只能得到上网快速登录脚本）  
3.  通过进入教学楼，得到固定mac，在寝室复制mac地址上网（教学楼都没有白名单，老师登录自己的账号才可以上网，也不可以）
## 开始实践
我首先开始查询网络上常见校园网的设备厂家，最出名的就是讯捷，还有天翼云等等网络，然后我在哔哩哔哩校园网里面查到了我学校的校园网的园区网接入控制系统厂商，***深澜***  
我开始在网络上查找各类深澜网络的信息，一种是网页认证还有一种是客户端认证，在Github上面也有不少项目对于深澜有研究  
深澜校园网系统很强，在对于防共享，多认证模式兼容，会话精细管理，计费精准，成本低对路由器兼容高  
我开始抓包，输入校园网的ip后在登录页面输入账号登录，得到了srun_ver": "SRunCGIAuthIntfSvr V1.18 B20221130这么一串，在豆包查询以后得到了这是**深澜 Srun 4K 认证计费系统**（第四代校园网认证体系）  
我开始了继续研究，这一部分有点抽象可以看看大佬的解法  
[huxiaofan1223的深澜portal分析](https://blog.csdn.net/qq_41797946/article/details/89417722)  
输入错误密码进行不变量的研究，发现challenge每次变化且返回值很大，在请求数据的14个中，发现有11个是不变值，研究对象就只有3个password,chksum,info这三个了，然后在js里面发现这个是md5加密，然后至于token就是之前的challenge，简单的字符串 拼接，然后用sha1加密得出chksum。md5加密以后在加密，当时看代码也是想了好久才解出来的，有种看着答案想原因的感觉

#### 校园网主流多设备检测技术总表  

| 检测层级                                                     | 检测技术名称           | 核心检测原理                                                 | 设备识别特征                                                | 对应对抗方案 / 工具                              | 生效场景                                     |
| ------------------------------------------------------------ | ---------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------- |
| **IP / 传输层（底层数据包检测）**网关直接解析包头，无加密规避 | TTL 生存时间检测       | 不同操作系统出厂默认 TTL 数值不同，路由器 NAT 转发会使 TTL 固定减 1，网关通过 TTL 数值差异判断多设备 | 同一上网 IP 下，同时出现 64、128 等多组 TTL 数值            | iptables 统一修改全网数据包 TTL，抹平数值差异    | HTTP/HTTPS 全流量生效，无法加密规避          |
|                                                              | IP-ID 数据包标识检测   | 各设备系统 IP-ID 计数器递增逻辑独立，NAT 共享后会出现多套独立的 ID 序列，被网关识别 | 单一外网 IP 下，存在多种 IP-ID 生成、递增规律               | rkp-ipid 工具，统一改写所有设备的 IP-ID 生成规则 | IPv4 全网流量通用检测                        |
|                                                              | TCP 协议栈指纹检测     | 不同系统 TCP 握手参数（MSS、SACK、窗口大小、窗口缩放系数）存在固定差异，可精准识别系统类型 | 同一账号 IP 下，同时出现 Windows、安卓、iOS 等多套 TCP 指纹 | 内核参数修改，统一 TCP 握手特征参数              | 所有 TCP 连接流量，加密流量也可检测          |
|                                                              | TCP 时间戳时钟偏移检测 | 每台终端内核时钟独立、速率不同，TCP 时间戳字段会记录时钟差异，多设备共享会出现多组时钟偏移 | 流量中存在多种时间戳增长速率、偏移量                        | 关闭 TCP Timestamp 选项，统一时钟特征            | 高阶检测，部分学校未部署                     |
| **应用层（HTTP 明文检测）**仅针对未加密流量                  | UA（用户代理）检测     | HTTP 请求头携带设备浏览器、系统信息，多设备上网会出现大量不同 UA 字段 | 同一 IP 下交替出现手机、电脑、平板等不同设备 UA             | UA2F 工具，统一改写所有设备 HTTP UA 头部         | **仅 HTTP 明文生效**，HTTPS 加密流量完全失效 |
|                                                              | HTTP 头部交叉校验      | 比对应用层 UA 信息与底层 TCP 指纹，信息不匹配即判定为代理共享 | UA 显示 Windows 系统，TCP 指纹为 Linux 路由特征             | 统一头部与底层协议栈特征，消除矛盾点             | 仅 HTTP 明文流量可检测                       |
| **网关 DPI 层**深度流量检测                                  | DPI 深度包检测         | 网关重组完整 TCP 会话，解析应用层协议，识别代理、隧道、异常并发流量特征 | 存在 VPN、代理、多级 NAT、异常高频连接特征                  | 流量混淆、伪装常规网页流量，规避特征识别         | 全流量生效，校园网高阶防护手段               |
| **AAA 业务层**账号会话检测                                   | 并发连接行为检测       | 单台设备 TCP 并发连接数有固定阈值，多设备共享会远超正常单机连接量 | 短时间内出现数百上千条并发 TCP 连接                         | 限流、均衡设备连接数，控制并发阈值               | 所有上网场景通用，深澜等系统默认开启         |

#### 核心工具功能精简汇总表  

| 工具名称 | 核心作用                                       | 对抗的检测类型               |
| -------- | ---------------------------------------------- | ---------------------------- |
| UA2F     | 统一改写所有内网设备 HTTP 请求 UA 头部         | UA 多设备检测、HTTP 头部校验 |
| rkp-ipid | 统一所有数据包 IP-ID 生成逻辑，抹平设备差异    | IP-ID 多设备特征检测         |
| iptables | 批量修改数据包 TTL、TCP 参数，统一底层流量特征 | TTL 检测、TCP 协议栈指纹检测 |

### 重点课堂总结

1. **底层检测（TTL/IP-ID/TCP 指纹）优先级最高**，HTTPS 加密也无法规避，是校园网主要防共享手段

2. **应用层 UA 检测局限性极强**，仅对明文 HTTP 生效，加密流量可天然规避

3. 所有对抗技术仅用于**规避多设备共享检测**，无法绕过校园网账号 Portal 认证准入机制  

     

### 再次实践  

那么我现在已经有了学姐的帐号了，可以登录学校的校园网络了，有些学校允许学生进行代理共享网络普通的电脑沙盒代理网络，直接开启热点就能用，有些是不允许的，那么我们应该怎么做呢  

这里的方案我主要看到的就是openwrt路由器的防检测了

##### 1. TTL 检测

- 检测原理：不同系统 TTL 不同，NAT 转发后暴露多设备
- **解决办法**：路由器统一强制修改所有出站数据包 TTL，全部抹平成统一值，消除系统差异

##### 2. IP-ID 检测

- 检测原理：各终端 IP-ID 随机 / 递增规律不同，可被识别多主机
- **解决办法**：使用 `rkp-ipid` 统一内核 IP-ID 生成策略，让所有设备流量表现为「单主机 ID 特征」

##### 3. TCP 协议栈指纹检测（MSS、SACK、WinScale）

- 检测原理：Windows/Android/iOS TCP 握手参数不一样
- **解决办法**：路由器统一固化 TCP 握手参数、关闭差异特征，全网流量统一为一套系统指纹

##### 4. TCP 时间戳偏移检测

- 检测原理：各设备时钟速度不同，时间戳增速不一致
- **解决办法**：关闭 TCP Timestamp 选项，彻底消除时钟偏移特征

##### 5. HTTP UA 多设备检测

- 检测原理：手机、电脑浏览器 UA 不同
- **解决办法**：部署 **UA2F**，所有内网设备 HTTP 头部强制统一成相同 UA

##### 6. HTTP 头部与底层指纹不匹配校验

- 检测原理：UA 是 Windows、TCP 栈是 Linux → 判定路由共享
- **解决办法**：上层 UA + 底层 TCP 指纹**全部统一一致**，消除特征矛盾

##### 7. DPI 深度应用层检测

- 检测原理：识别隧道、代理、异常流量行为
- **解决办法**：流量伪装、标准化流量特征，避免隧道特征、异常包、高频连接

##### 8. 并发连接数行为检测

- 检测原理：多设备 NAT 后连接数远超单机阈值
- **解决办法**：路由器做连接数均衡、限流，控制总体并发量模拟单机行为

 不过由于国内的校园网环境复杂多变，且每个学校的防护不同，可能会加入不同的检测方式，如时间戳检测和心跳包，来帮助，同时我还是很支持大家多尝试的，openwrt路由器是一个不同的板块，有不同的插件可以玩，当然玩机有风险，刷机需谨慎。大家可以自行探索后面的，多播提速和防检测，依旧现在最多的自动登录，这个快捷登录还是蛮多的，可以作为脚本挂载，很方便舒服，不用每次输入账号密码来登录
